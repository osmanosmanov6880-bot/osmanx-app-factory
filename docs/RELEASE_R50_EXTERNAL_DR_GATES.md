# OSMANX APP FACTORY — R5.0 independent DR operational gates

**R5.0 is an engineering acceptance package, not a production deployment or customer-data migration.** All executable code remains on a Draft PR based on R4.9; production SQLite and `main` remain untouched. All receipts explicitly return `productionCutoverAllowed=false`.

## Four engineering blocks

1. **Network and failure-domain preflight** (`r50-topology.mjs`). Requires fixed HTTPS root URLs for object storage, witness and optional alert receiver; validates DNS resolution and rejects private, loopback, link-local and identical public endpoints. Explicit synthetic loopback is permitted only with test confirmation. Different DNS/IPs are **not sufficient proof** of different providers, ownership, regions, operating teams or protected networks; the result states those limits.
2. **Tamper-evident evidence ledger** (`r50-evidence.mjs`). A separate 32-byte HMAC key signs each strictly limited, privacy-safe recovery PASS/FAIL receipt. Entries are linked by sequence and previous digest; the file and directory use private permissions, fsync and fail-closed writer lock. Raw CRM records, financial values and encryption keys never appear. An external immutable ledger-head anchor is needed to detect removal of the *entire* file.
3. **Signed operational recovery drill** (`r50-drill.mjs`). On the already authenticated R4.9 remote S3 + witness path, repeats independent signed SQLite restoration into a fresh private file, rechecks the signed remote head after restoration and measures elapsed recovery time and age of the last witnessed snapshot against explicit test limits. On failure it writes a sanitized FAIL receipt. Passing synthetic tests does **not** establish customer-data RPO or regional disaster readiness.
4. **Independent review and detached recovery** (`r50-approvals.mjs`, `ops/r50/`, CI). Requires three distinct trusted Ed25519 public keys (security, operations, data owner) and detached approvals covering the exact code commit SHA, signed catalog and evidence head, expiring within seven days. It refuses duplicate roles/keys, expired signatures and changed evidence. CI exercises a separate recovery Node process using S3, witness, signed manifest and external encryption keys, without the source vault directory. The review only approves a **controlled synthetic external drill**, never production cutover.

## Operator commands (no secrets in Git, chat or logs)

1. On a separately managed *test* host, export `OX_R50_STORAGE_ENDPOINT`, `OX_R50_WITNESS_ENDPOINT` and optional `OX_R50_ALERT_ENDPOINT`. Run `node ops/r50/preflight.mjs` and save its JSON result. Local HTTP requires both `OX_R50_CONFIRM_SYNTHETIC=YES` and `OX_R40_EPHEMERAL=YES`.
2. Generate a **new** independent 32-byte evidence signing key, store it in a 0600 file away from backup and witness keys. Export `OX_R50_EVIDENCE_KEY_FILE`, `OX_R50_EVIDENCE_DIRECTORY` and `OX_R50_TENANT_TOKEN` (the opaque HMAC tenant token). Run `node ops/r50/verify-evidence.mjs` to check saved acceptance receipts. Never publish the HMAC signing key.
3. Have three actual authorized reviewers independently sign the canonical message generated by `canonicalR50ApprovalMessage` from the exact `format: osmanx-r50-staging-review-v1` challenge. Store their signatures in a separate JSON file with roles `security`, `operations`, `dataOwner`. Export challenge/approvals/public-key file paths and run `node ops/r50/verify-reviews.mjs`. The tool checks signatures, not human identities or employment status.
4. For detached offline recovery, follow `docs/RELEASE_R49_INDEPENDENT_DR.md`. Its CLI uses only S3, an independently hosted witness, the trusted signed bundle and external keys, and writes a unique isolated SQLite snapshot. It must **never** overwrite the live database or execute payments.

## External services and acceptance gates not implemented by CI

- No cloud provider account, paid S3 bucket, real DNS/TLS, independently managed witness VPS or alerting subscription is provisioned by this repository. R5.0 does not verify public cloud billing, user ownership or independent provider control.
- DNS checks are point-in-time **and do not prevent DNS rebinding**; secure egress allowlisting, private networking and provider IAM/STS audit must be enforced externally. TLS clients validate certificates, but topology alone does not prove physical separation.
- Independently anchor the latest witness *and* evidence-ledger heads to a distinct immutable service, protect credentials in an audited vault and validate on-call notifications and restore permissions.
- Verify actual time-bound COMPLIANCE retention policies with legal/data-governance approval. CI's seven-day MinIO retention is disposable synthetic testing, **not a production retention recommendation**.
- RPO must be demonstrated against known last-committed production test transaction IDs, not merely the timestamp of the most recent backup. RTO must be measured with true external regional loss simulations.
- Review supplier image provenance and signatures; the R4.9 MinIO runner image is unofficial and digest-pinned for isolated CI only.
- Independent on-call, security, privacy, payment-processor settlement, live traffic fencing and actual PostgreSQL cutover checks remain open.

**Release policy:** accept R5.0 only after both PostgreSQL 15/16 real MinIO + detached CLI + evidence + review tests pass. Keep Draft. Never label a synthetic pass as production-ready.
