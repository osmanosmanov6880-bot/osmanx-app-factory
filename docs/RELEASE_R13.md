# OSMANX APP FACTORY · Выпуск R1.3 / Visual Grid Studio

**Дата:** 4 ноября 2026. **Основа:** R1.2. **Назначение:** реальная визуальная сборка страниц CRM и сайта с воспроизводимым экспортом. **Статус:** локальный MVP, не промышленная облачная услуга.

## 1. Сетка и Drag & Drop

`public/studio/editor.js`: палитра поддерживает HTML Drag and Drop; блок можно вставить до или после другого блока по положению указателя. Перемещение существующих блоков корректно учитывает изменение индекса. В конце страницы есть отдельная зона вставки. Для пользователей без мыши доступны кнопки добавления и перемещения, а также операции «Выше/Ниже». Это структурный DnD, **не** произвольное позиционирование с пиксельной точностью.

Поле `layout` у блока имеет значения `wide`, `half`, `third`. На компьютере CSS-сетка на 12 колонок отображает соответственно 12, 6, 4 колонки. На мобильных ширинах все блоки занимают одну колонку. Валидация отклоняет некорректные значения и не позволяет сделать формы, таблицы и крупные заголовки третью ширины. Разделители всегда полноширинные. Существующие страницы без поля `layout` сохраняют эквивалентное поведение: счётчик — половина, остальные блоки — вся ширина.

`src/common/pages.mjs`: `PAGE_SCHEMA_VERSION=4`. `src/site/model.mjs`: `schemaVersion=2`. Оба формата нормализуются сервером, а не доверяют данным браузера. Изменения проходят через обычные API с CSRF и проверкой версии страницы.

## 2. Связанные данные и интерфейс

- CRM `metric.entity_count` + `entity=custom:<slug>` — число активных записей пользовательской таблицы. Источник проверяется сервером фабрики; самостоятельная CRM запрашивает количество через `/api/entities/<slug>/rows?limit=1` с проверкой роли в API. Браузер не выполняет пользовательский SQL/JavaScript.
- `table.limit`: только 5/10/20; у пользовательских таблиц лимит передаётся в API, у встроенных отображаются первые N из разрешённой выборки.
- `form.successText`: настраиваемый текст уведомления только после успешной операции записи в защищённый API.
- В редакторе сведения о источнике выводятся как **предпросмотр**. Тестовые записи не являются настоящими данными клиентов.

`public/crm/pages.js`, `public/crm/app.css`: адаптивные блоки и проверка прав для счётчика. `src/site/model.mjs` и `public/site/site.css`: параллельная 12-колоночная компоновка с семантическими секциями. В автономные архивы включаются именно эти файлы.

## 3. Безопасность и обратная совместимость

Сохранены allowlist действий и типов, экранирование HTML, роли на API, защитная проверка CSRF, отделение данных клиентов от исходного ZIP. Никакой исполняемый JavaScript, SQL или произвольный сетевой адрес из дизайнера в конфигурацию не добавляется.

Сохранено чтение прежних CRM-страниц без `layout`, `limit`, `successText`. Операции изменения страницы перезаписывают её в новой валидной схеме. Для несогласованных старых релизов рекомендуется резервная копия и проверенный план обновления. Сайты по-прежнему не поддерживают автоматическое обновление уже установленных копий.

## 4. Проверки текущего выпуска

1. `npm run check` — успешно.
2. `npm test` — **31/31** Node-тестов; новые тесты проверяют запрет неверных размеров/ссылок/лимитов, рендер сайта, фабрику по HTTP, запись в SQLite и запуск экспортированной CRM.
3. `python3 tests/ui_r13_grid.py` — перетаскивание из библиотеки, выбор источника, отмена/повтор, сохранение; Chromium 1440 и 390 px с модельными API, без горизонтального переполнения.
4. `python3 tests/ui_r13_runtime.py` — рендер CRM/сайта, две равные колонки на компьютере, вертикальная компоновка на телефоне, 5 табличных строк и 17 в тестовом счётчике.
5. `python3 tests/ui_r12_workbench.py` — регрессия старой мастерской; успешно.
6. Проверка экспортов и запуск автономных примеров — в отдельном журнале упаковки.

**Честное ограничение QA:** полноценный браузерный E2E от Chromium до реального локального сервера ещё не подтверждён, ранее блокировался администраторской политикой среды. Node HTTP/SQLite и браузерные UI-тесты проверены раздельно. Нет нагрузочного теста или независимого аудита безопасности.
