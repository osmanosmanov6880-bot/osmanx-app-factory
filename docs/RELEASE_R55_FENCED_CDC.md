# OSMANX APP FACTORY R5.5 — independently fenced publishers and safe witness reconciliation

**Mode:** opt-in isolated synthetic CRM only, stacked after R5.4. Every release and recovery receipt retains `productionCutoverAllowed=false`. Production SQLite and `main` remain unchanged.

## Four substantive implementation blocks

1. **Authenticated cross-worker fencing authority.** `src/migration/r55-fence.mjs` provides a dedicated HTTP receiver and HTTPS client. The receiver persists a tenant-scoped, HMAC-signed epoch on a private 0700 state filesystem using `O_EXCL` locking, fsynced temp writes and atomic rename. Workers receive a signed lease with a monotonically increasing `epoch`, random `leaseId`, bounded TTL and nonce-bound fresh responses. Two independent callers cannot hold a valid lease simultaneously; an expired or superseded client cannot renew, assert or release an old generation. All requests and responses are authenticated with an independent 32-byte HMAC key and separate bearer token. Lost or stale lease state is *fail-closed*; no automatic lock stealing. `ops/r55/fence-server.mjs` provides a private-file-key, loopback-only, non-production service entrypoint. Real deployment needs separately operated TLS ingress, isolated credentials, durable HA, monotonic-clock management and audited access.
2. **Provider-side conditional S3 pointer writes.** `src/migration/r48-s3.mjs` now reads an S3 pointer with its provider ETag and can sign conditional `If-Match` / `If-None-Match` requests. Only `r53/head.json` accepts conditional mutations. The R5.3 publisher's new `publishFence` mode validates the signed lease immediately before and after provider-side conditional PUT and again before advancing the independent witness. A stale ETag is rejected instead of silently overwriting the latest pointer. Encrypted segments retain the original content-addressed immutable, COMPLIANCE Object Lock requirement. The non-fenced preexisting R5.3/R5.4 synthetic flow remains compatible and tested.
3. **Loss-of-ACK reconciliation without blind promotion.** `src/migration/r55-reconcile.mjs` addresses an S3 HEAD version uploaded before the independent witness was updated, or a witness update that succeeded but whose HTTP response was lost. It verifies the entire AES-GCM and HMAC encrypted segment chain, reads each provider's COMPLIANCE version, verifies the old independently witnessed pointer hash is an **exact prefix** of the candidate, compares **every captured event and after-image** to the local committed SQLite journal, then uses a fresh distributed fence to advance the original monotonic witness. The operation is idempotent when a witness is already at that signed checkpoint. An orphan with a corrupted segment, schema drift, wrong tenant or mismatched source row is refused. It never treats an orphan S3 head itself as a valid recovery point.
4. **Actual SQLite COMMIT-to-witness delay observations, negative tests and real CI.** `src/migration/r55-commit-latency.mjs` opens and commits a synchronous, explicitly authorized synthetic SQLite transaction, records an elapsed monotonic timestamp immediately after COMMIT returns, and measures until a matching independently witnessed S3 head is confirmed. The output includes sampled min/median/p95/max latency and budget checks. It does **not** equate SQLite statement timestamps with commit ACK, prove independent fsync, certify an RPO SLA, or eliminate loss when the primary dies before the next poll. Tests challenge two independent clients, epoch rollover and persisted authority restart, wrong HMAC/bearer, stale S3 ETag, orphan ciphertext tampering, divergent local journal, and lost witness responses before and after commit. PostgreSQL 15 and 16 CI run real disposable MinIO with COMPLIANCE Object Lock, the independently signed delta witness, separate fencing authority and a fresh SQLite transaction sequence after the inherited R5.4 280-event test. Recovery must include all 283 events and preserve the earlier financial record unchanged.

## Critical limitations: **fenced lease is NOT an atomic object write**

A remote lease by itself cannot prevent a worker from entering S3 after its lease expired if it was paused immediately after validation. A conditional S3 ETag protects the pointer from overwriting an **already changed** object, but when an old worker races a new writer while the pointer still has the same ETag, this is **not the same as an atomic, distributed fencing transaction spanning the lease authority, S3, and witness**. The highest validated independent witness remains the recovery authority; orphan states are verified before promotion. A production design must use a single server-mediated/conditional object writer with a durable epoch in the write transaction, or an equivalent infrastructure-proven atomic CAS/fencing protocol, plus recovery of lost acknowledgements and proven failover behavior. This PR is a synthetic engineering step, **not** a claim that all cross-region split-brain races are eliminated.

## Other production blockers

- Only the *opt-in synthetic* R5.3 captured SQLite journal is supported. The production factory has not enabled triggers, safe schema evolution, persistent CDC worker supervision, retry retention guarantees or a coordinated baseline watermark. Transactions committed before the capture installation and sessions are intentionally outside the journal.
- The CRMs, witnesses, fence receiver and MinIO in GitHub Actions share a **single runner** even when they have separate processes, listen ports, roots and keys. No actual geographically independent S3 account, remote VPS, on-call paging system or production payment processor was connected.
- The simulated delay is measured between **same-process SQLite COMMIT return** and **remote witness verification** under test conditions. It does not measure arbitrary production client acknowledgements, independently verified fsync or worst-case RPO during a primary/datacenter outage. `realTransactionRpoSecondsMeasured=false` and `zeroRpoCertified=false` in all new reports.
- The independent fence store is private and authenticated but not WORM anchored, replicated or supplied with a trusted monotonic network clock; a compromised admin of all fencing state and HMAC keys remains powerful.
- S3 object lock and conditional PUT behavior must be accepted on each provider, with versioned retention under real IAM and an external audit. No caller can treat generic HTTP 200 or a local receipt as delivery proof.
- New telemetry includes no customer names, payment details or plaintext passwords and does not perform payment execution, settlement, refunds, promotion or production database cutover.
- **Do not merge** the Draft PR chain or switch the live SQLite-to-PostgreSQL cutover merely because tests pass. Require human security review, real separate failure-domain drills, measured business load RPO/RTO and independently approved operations.

## Synthetic-only independent service execution

Create two separate 0600 files holding an independently chosen bearer token and a 32-byte hexadecimal HMAC key. Run on an isolated test host with `OX_R40_EPHEMERAL=YES`, `OX_R55_SYNTHETIC_ONLY=YES`, a private 0700 `OX_R55_PRIVATE_STATE_DIR`, `OX_R55_BEARER_FILE`, `OX_R55_HMAC_KEY_FILE` and `OX_R55_LISTEN_PORT` (1024–65535). Start `node ops/r55/fence-server.mjs` and connect clients through a manually configured secure tunnel or trusted TLS ingress. Never expose the raw loopback HTTP port or real secrets on a public interface. No production deployment is performed by this release.

**Engineering acceptance requires**: all R4.0–R5.5 unit tests plus a real MinIO signed-CDC E2E run for **both** PostgreSQL 15 and 16, with explicit signed witness and lost-ACK before/after tests. This document does not itself certify that CI passed.
