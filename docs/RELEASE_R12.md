# OSMANX APP FACTORY R1.2 — ТЕХНИЧЕСКИЙ ОТЧЁТ

**Дата:** 4 ноября 2026. **База:** R1.1. **Состояние:** локальный функциональный MVP, не общедоступный SaaS. **Дизайн:** OBSIDIAN, тёмный графит с золотыми акцентами; русскоязычные рабочие экраны.

## 1. Единое рабочее пространство

В фабрике добавлен `public/studio/workbench.js`. Мастерская получает от сервера **один owner-scoped снимок** проекта через `GET /api/studio/projects/:id/workbench` (только авторизованный владелец), включая страницы, пользовательские сущности, сценарии, диагностику и историю версий. Это уменьшает необходимость вручную переключаться между разрозненными экранами.

Шесть вкладок CRM: Главное, Страницы, Данные, Кнопки, Сценарии, Выпуск. В сайтах отображаются только применимые вкладки. Из мастерской можно включить или выключить сценарий и опубликовать/снять с публикации страницу через защищённые HTTP-запросы с CSRF-токеном и проверкой `revision`. Сохранение не происходит локальным подменом текста: изменения записываются на сервере и повторно загружаются из SQLite.

Глубокое редактирование блока использует уже существующий структурный редактор: выбранные `pageId` и `blockId` передаются в `pageEditor.open(project,{pageId,blockId})`. В R1.2 не заявляется свободный drag-and-drop canvas и не создаются неподдерживаемые элементы.

## 2. Декларативные действия кнопок

Для CRM-схемы страниц `PAGE_SCHEMA_VERSION=3`. Кнопка может выполнять только разрешённое действие:

- `navigate:page:<slug>` — перейти на существующую **опубликованную** страницу CRM;
- `notice` — показать текстовое уведомление, без выполнения кода;
- предшествующие типовые `navigate:clients`, `create:clients`, `create:tasks`, действия с пользовательскими сущностями и др.

Дополнительные параметры кнопки: `roles` (массив допустимых ролей), `confirm` (логическое значение), `confirmText` (текст вопроса), `message` (текст уведомления). Схема отклоняет некорректные роли, управляющие символы, переходы с обходом URL (`../`) и произвольный JavaScript или внешний fetch. Данные проходят безопасную текстовую обработку в DOM.

**Важная граница:** фильтр видимости кнопки на клиенте — это UX, а не механизм авторизации. Для реальных операций права проверяются соответствующими серверными API. Подтверждение не создаёт платёжных транзакций или иных возможностей сверх уже разрешённых операций.

## 3. Предэкспортная диагностика

`src/studio/diagnostics.mjs` проверяет все переходы из **опубликованных** страниц CRM. Ссылка на удалённую, несуществующую или неопубликованную страницу считается ошибкой. `GET /api/studio/projects/:id/export` и экспорт выпуска отказывают с кодом `409`, пока конфигурация содержит ошибки. Предупреждения, в отличие от ошибок, остаются видимыми, но не блокируют локальную сборку.

Это проверка **конфигурации**, а не аудит качества или кибербезопасности и не гарантия безошибочной эксплуатации.

## 4. Готовые отраслевые архивы

`scripts/build_industry_sample.mjs` генерирует пять демонстрационных независимых CRM — restaurant, dental, auto, beauty, retail. В каждой: стартовая отраслевая страница, «Памятка для команды», кнопка перехода с подтверждением (видна администратору/управляющему), кнопка уведомления для всех ролей, отраслевые таблицы и один редактируемый сценарий. В Restaurant CRM базовые клиенты и задачи остаются системными таблицами, поэтому число пользовательских таблиц может быть нулевым.

Независимый корпоративный сайт генерируется отдельным скриптом `scripts/build_site_sample.mjs`. Во всех шести ZIP есть `config/project.json`, `run.mjs`, манифест с SHA-256 и инструкции; реальные клиентские данные, пароли и сессии не переносились.

**Проверено:** все шесть архивов распакованы, серверы запущены независимо и ответили `200 OK` на `/api/health`. Это проверка запуска, не полное UI-E2E каждой отрасли.

## 5. Воспроизводимая проверка

```bash
npm run check
npm test
python3 tests/ui_r12_workbench.py
node scripts/build_industry_sample.mjs dental /tmp/dental.zip
node scripts/verify_package.mjs /tmp/dental.zip
```

Результаты текущего релиза: **28/28 Node.js тестов**, включая два R1.2 теста схемы и HTTP/SQLite/ZIP-проверки. Chromium c **mock API** успешно проверил вкладки, смену публикации, открытие настройки кнопки на 1440 и 390 px. Реальный browser-to-live-HTTP E2E не подтверждён из-за политики среды, запрещающей Chromium доступ к localhost; реальные HTTP API отдельно проверены тестами Node.js.

## 6. Ограничения

Нет облачной публикации, CDN/доменов/HTTPS для клиентов, реального эквайринга и возвратов, SMS/e-mail/мессенджер-интеграций, визуального языка произвольных API-операций, произвольной свободной сетки в редакторе, сборки Android/iOS, полноценного тестирования доступности и production-аудита. Любое публичное внедрение с персональными данными требует отдельного этапа инфраструктуры, безопасности, резервного копирования и юридической подготовки. Для стоматологии не реализована медицинская информационная система и не предусмотрено хранение диагнозов.
