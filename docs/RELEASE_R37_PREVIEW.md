# OSMANX APP FACTORY — R3.7 Engineering Preview

**Дата:** 6 ноября 2026. **Ветка:** независимая локальная разработка на основе R1.3 + дополнения R2.4–R3.7. Оригинальный код R2.3 недоступен и не был объединён. **Визуальный дизайн:** OBSIDIAN без изменений.

## Четыре крупных блока кода

### 1. Надёжная идентификация процесса, управляющего обновлением

`templates/deploy/upgrade.mjs` теперь использует **две составляющие** для проверки блокировки: PID и идентификатор запуска Linux-процесса (`/proc/<pid>/stat`, поле 22, вместе с `boot_id`). Это не позволяет чужому или вновь запущенному процессу с тем же PID навсегда заблокировать подтверждённое восстановление. Старые блокировки v1 поддерживаются, но при живом PID по-прежнему **не снимаются** автоматически. Без доступа к `/proc` поведение консервативное: блокировка считается действующей. При обычном применении нового релиза никакого самостоятельного «захвата» блокировки нет.

### 2. Проверка всех публичных адресов DNS и HTTPS

Добавлен `deploy/edge-audit.mjs`. Он проверяет DNS A/AAAA и — только по явному флагу `--live` — проверяет **каждый** публичный адрес независимо. TLS соединение привязывается к конкретному IP, но hostname и SNI остаются доменными; `/api/health` обязан вернуть нужный UUID, тип приложения и номер релиза. Отклоняются локальные/зарезервированные IP, редиректы, неверные TLS-сертификаты, чужие выпуски и ответы неизвестного вида. Если хотя бы один опубликованный адрес не проверен, общий `ready` остаётся `false`. Лимит — максимум восемь адресов (при большем количестве — явный отказ, а не неявная выборка).

```bash
node deploy/edge-audit.mjs --dns-only   # DNS, без HTTP/HTTPS
node deploy/edge-audit.mjs --live       # НАМЕРЕННЫЕ HTTPS-запросы к публичным A/AAAA
```

Это **проверка доступности из конкретного окружения**, не глобальный мониторинг всех провайдеров, не гарантия готовности платежей, формы записи или резервирования. Запускайте только на собственном разрешённом домене.

### 3. Безопасный отчёт об инциденте

Добавлен `deploy/incident-evidence.mjs`, объединяющий только фиксированные поля из `doctor`, истории обновлений и последней проверки устойчивости. Сырые тексты ошибок, `.env`, пути, адреса пользователей, содержимое запросов и строки SQLite в отчёт не включаются. По умолчанию отчёт полностью офлайн, а файл может быть создан **только вне каталога приложения** с приватными правами. JSON не является криптографически подписанным свидетельством — для подлинности отдельно используются Ed25519-отчёты Fleet.

```bash
node deploy/incident-evidence.mjs --out=/private/osmanx-incident.json
node deploy/incident-evidence.mjs --live --out=/private/osmanx-incident-live.json
```

Отсутствие ошибок в офлайн-проверках **не** устанавливает статус production-ready.

### 4. Синтетическая нагрузка Docker и воспроизводимая приёмка

`script/r37_docker_e2e.mjs` (путь в коде: `scripts/r37_docker_e2e.mjs`) разворачивает в Linux Docker две отдельные временные установки: CRM и сайт. Синтетические записи создаются через **реальный HTTP в контейнере**. Затем выполняются `SIGTERM`, повторный запуск, `SIGKILL`, повторный запуск и `PRAGMA integrity_check` SQLite с проверкой, что **все записи сохранились**. Перед тестом проверяется отсутствие публикации портов хоста, а после — удаление контейнеров и томов. Неуспешная очистка считается ошибкой теста и сохраняет местоположение установки для разбора.

```bash
npm run check
npm test
npm run test:r37
npm run acceptance:r37
npm run samples:r37 -- /private/r37-samples
npm run verify:samples:r37 -- /private/r37-samples
# На Linux runner с Docker Engine:
npm run docker:e2e:r37
```

`.github/workflows/r37-release-readiness.yml` содержит раздельные local-security и real-docker задачи. В Docker-job дополнительно вызывается предыдущий тест подписанного обновления/отката R3.1. **Наличие workflow не означает успешный запуск на GitHub**: в текущей среде нет Docker Engine, и job не выполнялся.

## Проверено в данной сборке

- Node.js 22.16.0, синтаксические проверки.
- **138/138 тестов**, завершение `npm test` с кодом 0, включая **13 новых** тестов R3.7.
- Шесть независимо экспортированных приложений: пять CRM и корпоративный сайт; локальный HTTP `200`, проверка идентификатора версии, наличие новых модулей в хешируемом манифесте.
- Полный архив и патч после сборки должны быть побайтово сверены; их окончательные контрольные суммы публикуются отдельно.

## Чего не проверяли

- Docker E2E в настоящем Docker Engine, Docker-сценарии с SIGTERM/SIGKILL на VPS и исходящие публичные IPv6/IPv4 TLS-запросы к реальному домену.
- Публичный деплой, реальную выдачу Caddy TLS-сертификата и полноценные браузерные E2E с живым backend.
- Сценарии с настоящими персональными данными и внешние аудиты безопасности.
- Совместимость с оригинальным отсутствующим R2.3, которая требует его исходников.

**Никакие автоматические платежи и публичные сервисы не активировались.**
