# OSMANX APP FACTORY R1.0 — релиз 4 ноября 2026

## Изменения

**Этап A — бизнес-шаблоны.** Пять `industry` для CRM: `restaurant`, `dental`, `auto`, `beauty`, `retail`. Источник данных — единый `src/studio/industries.mjs`. Для каждого проекта сохраняются сущности `project_entities` с валидируемыми связями и страницы `project_pages`. Автоматическое создание использует транзакцию. Сайт (`type=site`, `industry=business`) остаётся отдельным продуктом.

**Этап B — правила.** Три события: `client_created`, `visit_created`, `entity_created`. Для `entity_created` можно выбрать таблицу, поле select/text/boolean/integer и точное значение; действие — только создать задачу. Отсутствует выполнение пользовательского JS/SQL. Правило выполняется внутри транзакции записи; уникальный ключ в `automation_runs` защищает от повторного запуска одного события. Менеджер/администратор управляют правилами, сотрудники без права не допускаются. Дедлайн `due_days` — 0..365. Название задачи поддерживает подстановку доступных полей `{{field}}`.

**Этап C — интерфейс.** На русском добавлены выбор отрасли в мастере и центр «Мастерская проекта» с доступом к страницам, таблицам, версии, команде, экспорту и диагностике. В CRM форма выбора полей/условий для автоматизаций; основной утверждённый стиль OBSIDIAN сохранён.

**Этап D — дизайн и безопасное обновление/доставка.** Все основные панели (Studio, CRM, CMS сайта) приведены к согласованной тёмной палитре OBSIDIAN и проверены в статическом Chromium. SQLite-миграция расширяет допустимые отрасли в старых таблицах фабрики и сохраняет внешние ключи, а CRM мигрирует CHECK-ограничение старых правил. Стандартные ZIP содержат исходники, схему и страницы, **но не рабочие записи**. Предыдущие релизы R0.4–R0.9 функционально регрессионно протестированы в новой сборке. Перед обновлением реального клиента делайте офлайн-бэкап и проверяйте восстановление.

## Проверки

- `npm run check` — синтаксис серверных и браузерных файлов.
- `npm test` — 21/21 Node tests, включая реальные HTTP, SQLite, ZIP, транзакции, права, миграции и независимый запуск.
- `python3 tests/ui_r10_new.py` — взаимодействия в Chromium с моделируемыми API на 1440x900 и 390x844. Снимки `qa/r10_project_hub_*`, `qa/r10_industry_wizard_*`, `qa/r10_automation_builder_*`.
- Отдельный Chromium браузерный E2E через настоящий localhost не подтверждён в тестовом окружении. Статический UI и реальные серверные тесты не заменяют такой E2E.

## Известные ограничения

- Новые правила автоматизаций **не копируются** в шаблоны CRM вместе с базой, потому что относятся к данным конкретного развертывания. В новом проекте правила настраиваются отдельно.
- `applicationVersion: 0.4.0` в манифесте CRM сохраняется из-за контракта локального установщика; `package.json` имеет продуктовую версию 1.0.0. Нельзя считать любой старый ZIP автоматически совместимым без отдельной проверки и бэкапа.
- Действие автоматизации только `create_task`. Внешних событий/расписаний, email, SMS и банковских платежей нет.
- Стоматология пока хранит лишь контактные данные, записи и услуги; медицинские карты/диагнозы/рецепты не предусмотрены. Перед реальной обработкой любых персональных данных выполните оценку применимых правил, доступа, защиты и хранения.
- Режим приложения локальный; нет автоматического публичного деплоя и полноценной инфраструктуры SaaS.

## Развёртывание

`node server.mjs` в корне исходников. Node.js >=22.16; дополнительные npm-зависимости не нужны.
Сразу после запуска откройте http://127.0.0.1:4173/.

Создать демонстрационный самостоятельный ZIP: `node scripts/build_industry_sample.mjs dental /absolute/path/dental.zip`.
Для экспортированного CRM: `node run.mjs`, открыть http://127.0.0.1:4180/.
