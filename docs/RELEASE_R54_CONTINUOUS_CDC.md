# OSMANX APP FACTORY R5.4 — continuous synthetic incremental CDC and witnessed checkpoints

**Status:** New opt-in synthetic engineering code in a Draft PR stacked after R5.3. Not a production deployment. All APIs return `productionCutoverAllowed=false`, and `main` and real CRM SQLite remain untouched.

## Four large implementation blocks

1. **Bounded multi-batch transactional capture.** `readR53Committed` now supports real 250-record pages rather than failing at 251 records. It checks the **entire local** append-only sequence with `count == max(seq)`, verifies every known SQLite capture trigger, rejects a cursor ahead of local source and reports `latestCommittedSequence`, `hasMore` and pending count. It does not silently ignore unknown tables, changed schema or deleted journal entries. The existing R5.3 AES-GCM / COMPLIANCE S3 upload format and independent witness remain the only valid means of acknowledging a published event.
2. **Bounded resuming CDC worker and local concurrency lock.** `runR54SyncWindow` inspects the **remote independent witness** each cycle, publishes at most 1–32 separately locked 250-event pages, then reads the local SQLite journal again to report newly committed backlog. It never treats an unconfirmed S3 `head.json` upload as acknowledged. Only transient connection errors are retried (bounded exponential backoff); corrupt signatures, missing COMPLIANCE retention and unanchored pointers fail closed. A 0700/0600 `O_EXCL` per-tenant lease prevents two publishers on the same host. It is **not a distributed lease across servers**; stale locks cannot be automatically stolen.
3. **Observable backlog, privacy-safe HMAC receipts and explicit RPO limitations.** The report carries witnessed event sequence, current locally observed sequence, outstanding **committed event count**, and the age of the oldest pending SQLite **write-time hint**. A SQLite statement timestamp is **not** the instant a transaction was acknowledged; `realTransactionRpoSecondsMeasured=false` and `maximumRpoSecondsCertified=null` by design. Configurable backlog and hint-age budgets trigger an `alertRequired` flag. Each cycle can be written to a private 0600 append-only, HMAC-chained ledger with sanitized counts and an opaque tenant token; this ledger has **no independent immutable external anchor**. It is not proof of remote acceptance without consulting the actual witness.
4. **Dedicated synthetic cooperative process, negative tests and real MinIO/PG15+16 tests.** `ops/r54/worker.mjs` runs a bounded poll loop on an explicitly isolated SQLite fixture with private file-based keys, cooperative SIGINT/SIGTERM, safe nonzero error/alert exits, and per-cycle HMAC receipts. Tests cover a 300-event 250/50 split, restart with zero duplication, stale lock, tampering and missing trigger, transient upload retries, missing S3 WORM, corrupt local sequence, signed-evidence forgery, concurrent publisher denial and safe stop. The E2E workflow uses a genuine synthetic versioned MinIO COMPLIANCE bucket and PostgreSQL 15/16. After the R5.3 sealed baseline and four-event replay, it commits 275 more synthetic tasks, witnesses a 250-event segment, demonstrates a 25-event backlog alert, catches up to sequence 279, and restores the first and last burst tasks plus existing payment through the full signed S3 history. It then takes down the actual delta witness HTTP listener during another commit and checks it cannot be reported as ready, before resuming to sequence 280.

## Operator: isolated synthetic fixture ONLY

Run `node ops/r54/worker.mjs` on a test machine with both `OX_R40_EPHEMERAL=YES` and `OX_R54_SYNTHETIC_ONLY=YES`. The source must already have been explicitly instrumented using `installR53Capture(db,{syntheticOnly:true})`; the worker **will not install triggers on your behalf**. Supply a private `OX_R54_EPHEMERAL_ROOT` folder (mode 0700) and `OX_R54_SOURCE_SQLITE` file inside it (0600). It refuses a file outside the fixture root or an uninstrumented source.

Required project and remote scope: `OX_R54_PROJECT_ID`, `OX_R54_SIGNED_MANIFEST_SHA256`, `OX_R54_BASELINE_ARCHIVE_ID`, `OX_R54_S3_ENDPOINT`, `OX_R54_S3_BUCKET`, `OX_R54_S3_REGION`, `OX_R54_S3_ACCESS_KEY`, `OX_R54_S3_SECRET_KEY`, `OX_R54_WITNESS_ENDPOINT`. Supply private token/HMAC files `OX_R54_WITNESS_TOKEN_FILE`, `OX_R54_CATALOG_KEY_FILE`, `OX_R54_DELTA_KEY_FILE`, `OX_R54_WITNESS_KEY_FILE`, `OX_R54_EVIDENCE_KEY_FILE`, each separate (0600). Set `OX_R54_LEASE_DIRECTORY` and `OX_R54_EVIDENCE_DIRECTORY` on private local filesystem. `OX_R54_LOOPBACK_TEST=YES` is only for disposable local testing.

Optional bounded parameters: `OX_R54_BATCHES` (default 6, maximum 32), `OX_R54_CYCLES` (default 1, maximum 10000), `OX_R54_POLL_MS` (default 1000), `OX_R54_MAX_BACKLOG` (default 0), `OX_R54_MAX_HINT_AGE_MS` (default 60000), `OX_R54_RETRIES` (default 2), `OX_R54_RETRY_BASE_MS` (default 75). A zero-backlog `alertRequired=false` value applies only to **the observed synthetic journal window**. A caught-up state is not independently anchored in the local HMAC file and does **not** certify production zero RPO.

The process exits with code 3 if its final observed window exceeded the configured backlog/hint budget and with code 4 for unsafe configuration, invalid external witness, COMPLIANCE or network errors. No actual SMS/email/pager escalation is implemented by this CLI; a service supervisor is needed to schedule/restart it and an external monitoring service to act on its nonzero status.

## Still-blocking production requirements

- This captures only a synthetic CRM *after* the R5.3 setup and signed baseline. It does not cover prior uninstrumented transactions, unsupported DDL/new tables, sessions, third-party payment settlement side effects, or an existing production SQLite database.
- `write-time hint` ages are not true transaction-commit timestamps; verified recovery-point objectives require durable commit watermarks, measured outage instants and proof that source-journal commits are continuously replicated and durably recoverable offsite.
- An empty queue at a sampled instant does **not** eliminate the risk of data lost between polls; an offsite outage can still lose pending local events on simultaneous primary host failure. No synchronous cross-region ACK before client-facing transaction success is implemented.
- The local O_EXCL lock does not prevent publishers on two different hosts from racing a remote S3 HEAD. A production distributed lease/fencing epoch and safe recovery from *upload complete but witness ACK lost* remain required.
- Immutable S3 object-version protection and an authenticated witness are checked, but all CI services share one disposable runner. There is no real independent cloud account, physically separate host or provider IAM audit, real on-call service or production cutover approval.
- Local HMAC audit evidence is not independently anchored in a remote WORM audit service; offline administrators can truncate/remove entire local evidence files.
- The dependency R5.3 detached restore tests and the R5.4 full suite must pass on both PostgreSQL 15 and 16 before treating R5.4 as accepted. Keep PR Draft and `main` untouched.

**Engineering status target:** confirm bounded catch-up and truthful backpressure/lag reports on synthetic data. Never claim near-zero production RPO or execute financial side effects.
