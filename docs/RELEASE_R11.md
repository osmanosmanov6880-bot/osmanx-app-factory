# OSMANX APP FACTORY R1.1 · Три инженерных этапа

**Дата:** 4 ноября 2026. **Статус:** локальный функциональный MVP. **Технологии:** Node.js >=22.16, SQLite, HTML/CSS/JS, без обязательных npm-пакетов. **Интерфейс:** русский, тема OBSIDIAN.

## I. Повторно используемые бизнес-сценарии

**Раньше:** правила автоматизации сохранялись исключительно внутри уже запущенной CRM. При клонировании и экспорте шаблона новый клиент получал пустой список правил.

**Теперь:** фабрика сохраняет до **30 сценариев в конфигурации проекта**; принимает условия по полям пользовательских таблиц; поддерживает изменения с проверкой версии, удаление и имитацию срабатывания без записи в базу. Сценарии переносятся в копии проектов, JSON-шаблоны, релизы и автономные CRM.

Где найти: откройте **Мастерскую проекта → Сценарии для шаблона** (это не то же самое, что действующие правила внутри работающей CRM). Доступны события: добавлен клиент, добавлен визит, создана запись пользовательской таблицы. Результат: локальная задача. Можно задать приоритет, срок 0–365 дней, условие на `text`, `select`, `boolean`, `integer` и интерполяцию значений `{{field}}` в названии.

Особенность безопасности: **сценарии устанавливаются только при первом создании пустой базы самостоятельной CRM**. Уже работающие экземпляры не теряют свои правила и не получают без согласования изменённые шаблоны. При переносе действующих бизнес-процессов с реальными данными потребуется запланированное обновление и проверка миграции.

API с владельческим доступом:

- `GET|POST /api/studio/projects/:id/workflows`
- `PATCH|DELETE /api/studio/projects/:id/workflows/:workflowId`
- `POST /api/studio/projects/:id/workflow-preview`

Представление `automationPresets` присутствует только у CRM-проектов. Никогда не передаются созданные задачи, журнал запусков, клиентские данные и учётные записи.

## II. Импорт клиентской базы CSV

**Что работает:** файл CSV → проверка без записи в базу → подсчёт новых, дублирующихся и некорректных записей → явное подтверждение → транзакционный импорт → обновление списка клиентов. Экспорт в CSV для переноса данных. Только для ролей **администратор** и **менеджер**.

Где найти: откройте **Клиенты** внутри CRM, используйте кнопки **Импорт CSV** и **Скачать CSV**. Заголовки CSV (строго пять, любой порядок):

```csv
full_name,phone,email,source,notes
Анна Петрова,+79995554433,anna@example.com,referral,Первый визит
Иван Сидоров,+79994443322,,walkin,Постоянный гость
```

Значения `source`: `unknown`, `walkin`, `social`, `referral`, `website`, `other`. Для телефона/почты — отдельная валидация. Поддерживаются UTF-8 c BOM, `,` и `;`, кавычки и встроенные переносы строк. Дублирующиеся записи по нормализованному телефону или email **не перезаписываются**. Неверные строки не импортируются; preview показывает первые ошибки. В одной загрузке максимум **500 записей** и **115 КБ**, экспорт максимум **5000 клиентов**. Формулы Excel нейтрализуются при экспорте; массовый импорт не запускает лавину автоматических задач.

API: `GET /api/clients/export`, `POST /api/clients/import-preview`, `POST /api/clients/import` с `confirm:true`.

**Важно:** это импорт/экспорт контактной базы, не инструмент автоматического сбора персональных данных. Перед использованием обеспечьте согласия, ограничения доступа и правомерную обработку.

## III. Независимая проверка ZIP

`node scripts/verify_package.mjs /абсолютный/путь/к/клиентской-CRM.zip`

Проверяет структуру ZIP, manifest version, соответствие SHA-256 каждого вложенного файла записи в манифесте, необходимый исходный код, тип проекта, конфигурацию и отсутствие runtime-баз `data/`, `.sqlite`, `.env`, и известных ключей паролей/сессий в JSON-конфигурации. Ошибка приводит к ненулевому коду завершения. Работает офлайн.

**Ограничение:** SHA-256 подтверждает целостность внутри архива, но **не аутентичность поставщика** — злоумышленник может заменить и файл, и его контрольную сумму. Нужна подпись релизов и доверенная схема доставки для production.

## IV. Автономные отраслевые примеры

Скрипт `node scripts/build_industry_sample.mjs dental /путь/dental.zip` генерирует **чистую** CRM для ресторанов, стоматологий, автосервисов, салонов красоты или магазина одежды. С R1.1 каждый пример содержит **один редактируемый реальный сценарий** с условием, подобранным под отрасль. Никаких настоящих клиентских записей или пользователей в архиве нет.

## Проверка и ограничения

- `npm run check && npm test` — **26 из 26 Node.js тестов**, реальный HTTP/SQLite и ZIP.
- `python3 tests/ui_r11_workflows.py` и `python3 tests/ui_r11_csv.py` — Chromium на **1440px и 390px**, UI с **имитированными API-ответами**, не полноценный browser-to-server E2E.
- Прямое браузерное E2E к локальному серверу в тестовой среде недоступно по политике браузера.
- Нет реального эквайринга, облачного деплоя, платёжного провайдера, SMS/email-интеграций, свободной drag-and-drop сетки, сертификации медицинских данных, мобильного native-app генератора. Установленные CRM **не синхронизируют** сценарии фабрики автоматически.
- SQLite в используемой версии Node выдаёт предупреждение experimental. Для публичного многопользовательского коммерческого SaaS необходима отдельная проверка СУБД, безопасности, резервирования и права на обработку персональных данных.
